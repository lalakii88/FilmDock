## 已实现的闭环

手动/文本导入剧本 → 规则拆镜并编辑 → 建立资产与参考 → 选择镜头 → 演示或自定义CLI/API生成 → 归档新候选 → 手动采用 → 铺排和修剪 → 连续预览 → 单独导出MP4或完整项目ZIP → 新目录导入续做。

CLI以程序和参数数组执行，shell=false，支持stdin及request.json。同步API支持JSON结果URL、Base64和直接媒体二进制；异步API支持POST提交、GET/POST查询与自定义字段映射。请求和查询不在渲染进程中执行。

任务保存提交时的提示词、时长、参考媒体ID和不含密钥的连接配置快照。重复clientRequestId返回同一本地任务；提交结果不明时保留submission_unknown，不自动再下单。已有远端ID或下载定位信息的任务可以恢复。暂停只停止本地进程或轮询，不保证远端取消或停止收费。

## 与0.1需求草案的差别

- 使用事务队列加临时文件原子替换JSON，尚未使用SQLite。
- 单个当前工作区；切换前需要手动导出ZIP保留项目。未提供多项目列表。
- 资产和镜头保留引用与生成候选，尚未实现完整不可变资产版本库或自动连续性检查。
- 拆镜为本地分段规则，没有接通语言模型进行语义拆解。导入只支持TXT和Markdown，没有DOCX/PDF/OCR。
- 时间线以一条主视频序列为主，可保留或静音原声。A1是原声展示，不是可独立编辑的音频轨；尚无独立音频导入、分割、变速、转场、字幕或混音。
- 支持视频片段修剪、重排、删除与时间线撤销重做；编辑以秒显示，导出对齐项目帧率。没有专业剪辑软件的逐帧交互体验。
- 没有费用估算、预算预留、多候选批量提交和生产级并发调度；真实调用前只做单次费用确认。供应商原生幂等键尚未配置，本地去重不能保证平台恰好一次。
- 部分低层任务和打包操作仍在主进程中，媒体任务通过异步子进程处理；大项目需要后续工作进程及流式打包。
- 输出做文件签名检查并尝试ffprobe探测；没有ffprobe时不承诺文件可完整解码。渲染或播放器将继续发现损坏媒体。
- 项目格式为0.2.0-demo，未实现与需求阶段0.1.0 JSON Schema的迁移。
- 不生成PR、Resolve、剪映原生工程，也没有OTIO适配。

## 数据和执行边界

渲染进程关闭Node集成，启用上下文隔离与沙箱；preload仅暴露业务接口。协议媒体请求按项目媒体ID定位，不能直接指定本机任意文件。导入路径检查、ZIP展开上限、SHA256清单和媒体归档已实现。

CLI是用户主动配置的本机程序，拥有其本地权限。本版不下载或自动运行网络插件；HTTP结果不能要求读取本地文件。真实调用的秘密字段通过系统safeStorage加密保存；安全存储不可用时只保留在内存中，不回退到明文文件。任务日志和项目交接不包含连接配置快照、密钥或临时下载定位。

单文件导入上限100MB，交接ZIP导入上限100MB，展开内容上限256MB和1万项。项目数量和媒体大小目标仅适合Demo。ZIP导出通过内存打包，后续应改流式归档。稳定ID保留，导入媒体在接收目录重新归档，因此没有对开发机绝对路径的依赖。

## 继续开发的推荐顺序

1. 在用户Windows机器验证便携包、常用平台CLI及API、FFmpeg路径与系统密钥存储。
2. 将JSON仓储迁到SQLite，完善项目列表、迁移、事务和显式备份恢复。
3. 按实际供应商补上传适配、模型能力范围、参考角色映射与费用信息。
4. 补资产版本、剧本版本及下游变更复核；将CLI和打包移到工作进程。
5. 再扩时间线、外部剪辑软件交换和跨项目复用，不先堆未经验证的平台按钮。

## 重建和测试

锁文件提供依赖版本。正常 `npm ci` 后 `npm start` 可运行源码，`npm test` 跑核心测试。Windows打包命令为 `npm run package:win`；无需Wine，Electron Packager会下载目标运行时并打包。

tools/test-ui.mjs与tools/test-browser.mjs在本次Linux环境用Electron的headless Ozone模式验证，文件对话框仅在测试进程中替换为指定路径。FILMDOCK_TEST_MODE只用于测试隔离，不改变正式启动的单实例约束；不要将test-results或本机凭据加入分发包。

本次交付保留源码供继续制作，尚未指定开源许可证，也没有创建或发布GitHub仓库。
